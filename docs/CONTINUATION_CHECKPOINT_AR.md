# نقطة الاستمرار — WhatsApp Group Responder App

التاريخ: 2026-08-11

## الوضع الحالي

- مشروع السيرفر: `whatsapp_group_responder` يعمل على Termux مع Baileys وTelegram وREST API.
- API المحلي أثناء الاختبار: `http://127.0.0.1:8787/api/v1`.
- Device Enrollment يعمل، والموافقة تصل عبر Telegram.
- تمت إضافة وضع فتح نافذة ربط التطبيقات بلا حد يدويًا في مشروع السيرفر: القيمة `DEVICE_ENROLLMENT_WINDOW_SECONDS=0` تعني أن النافذة تبقى مفتوحة حتى الضغط على «إغلاق الربط» في Telegram.
- مهلة طلب الربط الفردي ما زالت منفصلة عن نافذة الربط، لذلك قد يظهر للتطبيق أن الطلب السابق انتهى رغم أن نافذة الربط نفسها ما زالت مفتوحة.

## تطبيق Android / Flutter

- التطبيق موجود في هذا المستودع ويُبنى عبر GitHub Actions.
- البناء مخصص ARM64 Release وبهوية توقيع ثابتة للتحديثات المستقبلية.
- الإصدار الحالي في `pubspec.yaml`: `0.1.2+3`.
- الربط الحقيقي مع API وTelegram نجح على الهاتف.
- DeepSeek API نجح على الهاتف.

## المطلوب الحالي عند الاستمرار

### 1. تجربة انتهاء طلب الربط

المستخدم لا يريد رسالة مربكة مثل «انتهت مهلة طلب الربط» وكأن نافذة استقبال الربط أُغلقت.

السلوك المطلوب:
- إذا انتهى طلب ربط فردي فقط، يظهر توضيح هادئ بأن الطلب السابق انتهى ويمكن إرسال طلب جديد.
- بمجرد الضغط على «طلب ربط التطبيق» تُمسح الحالة القديمة فورًا ويُنشأ طلب جديد.
- نافذة الربط المفتوحة في Telegram تبقى مستقلة عن حالة الطلب الفردي.

### 2. تنسيق رسائل DeepSeek

DeepSeek يعيد Markdown مثل:

```text
## عنوان
**نص عريض**
- قائمة
``` 

يجب ألا يعرض التطبيق رموز Markdown خامًا.

المطلوب:
- عرض رسائل المساعد باستخدام Markdown renderer حقيقي.
- دعم العناوين `# / ## / ###`.
- دعم **bold** و*italic* والقوائم والاقتباسات وinline code وcode blocks والروابط.
- إبقاء رسائل المستخدم كنص عادي.
- النسخ السريع ينسخ النص الأصلي كما أرسله DeepSeek.
- «استخدام كرد» يستخدم النص الأصلي، ولا يحول Markdown إلى تنسيق مرئي داخل قاعدة الردود من تلقاء نفسه.
- المحافظة على RTL للعربية وقراءة الكتل البرمجية بوضوح.

- آخر GitHub Actions للإصدار `v0.1.2` نجح.

## قبل التسليم القادم

عند استكمال العمل في محادثة جديدة:
1. راجع الملفات السابقة من `main` ولا تفترض أنها ما زالت كما هي.
2. شغّل/تحقق من `flutter analyze` و`flutter test` وAndroid Release build في GitHub Actions.
3. اختبر أن Markdown أثناء Streaming لا يسبب كسرًا بصريًا ملحوظًا، وليس فقط الرسالة بعد اكتمالها.
4. اختبر طلب ربط جديد بعد انتهاء طلب سابق مع بقاء نافذة Telegram مفتوحة.
5. بعد نجاح CI، سلّم APK ARM64 Release للمستخدم هنا.
